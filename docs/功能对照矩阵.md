## 结果引用规则

- `evaluation/results/local_benchmark.json` 的 16 道检索题来自人工构造、确定性测试语料；SQL 项各为 6 道。它们是工程契约验证，不是端到端 Agent 准确率。
- 学习手册中的 34/40 和 28/32 是作者确认的异机实测汇总；不是本仓库 `local_benchmark.json` 或新建 `retrieval-v1` 的结果。旧两组逐题原始记录和旧 32 题仍待归档，不能声称已经由本仓库独立复核。
- 题集结构完整（40 题、9 张表、标准 SQL 可执行）只代表评测输入准备完成，不代表 Agent 已经答对 40 道。
- DB-GPT 的产品能力、源码和评测结论不得并入 `data_platform/` 的成果。

## 五个简历点的工程落地顺序（设计，不代表已验收）

模块级接口、数据结构、实施顺序和验收门槛见[简历五点工程设计与验收方案](简历五点工程设计与验收方案.md)；逐步学习和面试讲法见[主手册 8.3.1](../../学习文档/01-项目学习/数据智能平台-项目学习与面试手册.md#lesson-8-3-1)。这里仅保留速查待办，避免把“计划补齐”误写成“已经跑通”：

1. **Harness：** 保留 Provider、AgentRunner、ToolRegistry、State 四个核心职责和原生 Tool Calling 主链；协议测试固定覆盖多工具、非法参数、未知工具、轮次上限及工具错误回传。现有代码与确定性测试已覆盖基本路径，下一步逐项对照测试清单补缺口。
2. **State 与 Trace：** 当前 RunStore 已保存 Event/Checkpoint，`AgentRunner.resume()` 可在限定状态下继续。若要做到新进程恢复，需持久化不含密钥的模型/数据源/知识库/工具绑定，并用租约/心跳识别硬崩溃后遗留的 `RUNNING`；重建工具后再加载 Checkpoint。按“工具前、工具后未保存、保存后、硬崩溃、并发抢恢复”验证重复执行与版本冲突。当前只读工具不等于外部副作用 exactly-once。
3. **SQL 安全：** 保留 SQLGlot、SQLite 只读连接、authorizer 与资源限制；用固定有效/危险/错误语句逐题检查允许、拒绝、结构化错误和最终回答。不要把固定用例通过率说成对任意 SQL 的安全保证。
4. **Hybrid RAG：** 保留 `KnowledgeStore` 的 FTS5/BM25、向量和 RRF；新 32 题、19 份 Schema/规则/指标说明、Manifest、校验器和专用评测脚本已加入项目。下一步才是运行 Jina 检索并归档逐题前五排名；当前知识库依赖人工导入，不自动同步实时 Schema，JSON 指标目录没有运行时接入。
5. **Evaluation：** 保留 40 题九表业务题和 `run_agent_eval.py`；把每次运行的配置、题集/数据库哈希、逐题 JSONL、人工复核表归档。32 题检索、工具故障和中断续接分别出报告，不合并分母。若异机原始文件找不到，按同一方案重跑并标新日期，不能用预期结果补造逐题文件。

验收时每一点都应能回答“源码在哪里、输入输出是什么、怎样失败、测试或原始记录在哪里”。本轮只完善设计与教材，**没有执行新的模型评测，也没有宣称上述待办已经完成**。
