# DataPilot 新版实现与评测说明

## 1. 用一个请求理解项目

分析员直接问「各渠道有多少笔订单」，再追问「只看官网呢」。想保留哪次结果，就在那条回答下生成报告。报告保留本轮的 SQL 与结果，需要分享时再选接收人。

| 顺序 | 执行者 | 实际工作 |
|---|---|---|
| 1 | FastAPI | 校验登录和工作区成员，创建任务，绑定预置的订单数据源。 |
| 2 | LangGraph 的准备节点 | 加入会话历史。用户指定规则时加载其生效版本和相关资料。 |
| 3 | DeepSeek | 看到问题和工具定义，提出带调用编号的工具请求。 |
| 4 | 工具执行节点 | 查验参数与允许的工具，执行 SQL 或检索资料，带原调用编号回传结果。 |
| 5 | 报告与确认共享 | 选中一轮带查询证据的回答后，复用它的检查点生成报告，暂停在共享确认。 |
| 6 | 共享节点 | 确认后重新检查成员权限，用任务 ID 防止重复共享。 |

## 2. Agent Harness 与任务编排

学习时先读 `Agent.ask_model`、`Agent.execute_tools` 和 `Agent.after_model`。模型提出调用，程序通过条件路由决定该执行工具、回到模型、生成报告还是结束。注册表提供 JSON Schema，收到的调用参数由程序再次校验。

以下节选省去了错误处理和 Trace。收到一个工具调用时，关键是把结果和原来的调用编号配对。

```python
# call 是模型返回的一次工具请求，args 是解析和校验后的参数
result = registry.execute(name, args)
# 将数据库结果或结构化错误作为 tool 消息交还给模型
messages.append({
    "role": "tool",
    "tool_call_id": call["id"],
    "content": json.dumps(asdict(result), ensure_ascii=False),
})
```

一次字段拼错的情况，工具会返回 `unknown_column`。结果带原来的 `tool_call_id` 回到模型。模型可以先读表结构再改 SQL。执行层限制 8 轮模型请求、每轮最多 4 个工具调用以及累计 3 次工具错误。越权、写语句及未知工具会触发终止。Trace 记录事件、耗时、错误和证据编号。

**面试讲法**　我用 LangGraph 管理执行状态和分支。模型只提出工具请求，项目的执行层决定是否放行、如何回传和何时结束。我能按任务 ID 还原一次失败发生在模型、参数校验还是数据库。

## 3. 人工确认与断点续接

会话历史用于下一次提问。检查点则保存一次任务的执行位置。待审批任务用任务 ID 作为 LangGraph 的线程标识，从数据库恢复原报告，不需要再次调用模型或执行 SQL。

模型发现指标口径有歧义时，可在查数前调用 `clarify_metric`。图停在专用澄清节点，页面展示选项。用户选择后，同一任务恢复，选择作为工具结果回到模型。本轮采用用户确认的临时口径，并在回答中注明与默认规则的差异。

先持久化批准或拒绝，再恢复图。同一任务通过数据库锁串行提交审批。写入共享时检查发起人、接收人的工作区权限，按任务 ID 对写入去重。审批默认 24 小时内有效。接收者只能打开指向自己的站内报告。

## 4. 数据访问与执行安全

业务库保存 `orders` 和 `refunds` 等样例表。应用库保存用户、会话、任务、检查点与知识切片。业务查询使用专门的角色，只授权读取允许的业务表，模型无法传入连接串或自选业务库。

静态检查用 PostgreSQL 方言解析 SQL，限制为单条只读查询并检查表、函数和语句结构。执行阶段再用只读事务、3 秒语句超时及 100 行返回上限。返回上限限制输出规模，语句超时限制数据库执行时间。样例数据用合成记录演示，模型会收到任务所需的查询结果。

## 5. Hybrid RAG 与规则版本

Jina Embeddings v3 将文档切片和问题分别转成向量。pgvector 做精确余弦搜索，BM25 按英文标识符和中文二字词片找关键词，RRF 按排名合并。两路用同一个 PostgreSQL 快照中的有效切片。新版本先生成向量，再由应用库事务切换有效版本。

提问前可选用已发布的指标规则，检索可补充相关说明。比如同一订单有两笔成功退款，按「发生退款的订单数」计算时应使用去重计数。样例有 4 个 web 订单和 4 个 app 订单。两组各有 1 个成功退款订单，成功口径均为 25%。如果规则把待处理退款也计入，web 变为 50%，app 仍为 25%。

**面试讲法**　关键词能命中字段名，向量能匹配近义问法。我用同一套生效资料跑两路召回，再把规则版本与 SQL 证据写进报告。规则更新时，可以复核差异出在定义还是查询。

## 6. Agent Evaluation

简历采用项目负责人确认的新版复测汇总。40 道业务题经程序判分和人工复核，通过率 **85%（34/40）**。32 道检索题的 **Recall@5 为 87.5%（28/32）**，按前 5 条是否命中题目指定来源计数。本仓库收录判分方案和本地功能验证，逐题复测记录与当次完整配置未随汇总存放。

下面给出分层判分方案与示例，便于独立复核或开展后续对照实验。

| 项目 | 固定输入 | 判分 |
|---|---|---|
| SQL 结果 | 题目、样例库快照、参考结果与数值容差 | 对比列、行与数值。仅在题目要求顺序时比较顺序。 |
| 最终回答 | SQL 证据、指标版本、答案和判分要求 | 检查数字、分组、时间范围和引用。语义结论人工复核。 |
| 检索前五命中 | 问题、资料版本、相关来源编号 | 前五出现至少一个指定资料记一次命中，报告分母、未命中题与各路配置。 |

示例题记录包括 `id`、`question`、`source`、`rule_version`、`expected_rows`、`required_sources`。每次运行保留数据库快照版本、模型配置、任务 ID、检索结果、SQL 结果、最终答案及各项独立结论。复测前冻结题集和规则版本，失败可沿 Trace 定位到检索、SQL 或回答环节。

### 一条新版评测题样例

下例只定义题目和标准结果。初始化样例库时固定支付月份，复测时把 `2026-11` 与数据库快照一起记录。

```json
{
  "id": "refund-by-channel-001",
  "question": "按渠道计算 2026 年 11 月已支付订单的成功退款率。",
  "source": "orders",
  "rule_key": "refund_rate",
  "rule_definition": "仅计成功退款，按订单去重",
  "expected_columns": ["channel", "paid_orders", "refunded_orders", "refund_rate"],
  "expected_rows": [["app", 4, 1, 0.25], ["web", 4, 1, 0.25]],
  "required_sources": ["refund_rate"],
  "numeric_tolerance": 0.0001
}
```

复测按 `case_id` 保存逐题结果。程序先核对 SQL 结果，人工再检查回答有没有说清月份、去重和退款条件。检索评测直接对知识库查询排名，分开记录关键词、向量和融合结果。两套题各自使用自己的分母，最终保留失败题和配置。

## 7. 本轮工程验收

- **看完再生成报告。** 使用真实模型查询 2026 年 11 月订单，Web 和 App 各 4 笔。追问「只看官网呢」得到 4 笔。选中追问生成报告、再选接收人，确认前后检查了接收权限，执行记录没有新增模型或 SQL 调用。
- **查数前确认口径。** 在同一份样例数据中，选择只计成功退款后，Web 退款率为 1/4（25%），任务为 `0d5fd89e546a4ca48a1bacb08aa5c38d`。选择同时计入处理中退款后为 2/4（50%），任务为 `5a3bed752960479aaa8aa8eb2254d8e3`。两题都先暂停，再按所选条件查数，最后对照了 SQL 和结果。

以下是之前的功能验收记录。

- 使用真实 DeepSeek Tool Calling、Jina Embeddings v3 和 PostgreSQL 进行功能验收。报告任务 `961035ada11c494eb295edd53312ccd9` 只计成功退款，App 和 Web 都是 25%。
- 发布包含待处理退款的规则后，任务 `43a7bc85a74344a693d66c97e85bd5d9` 的 Web 结果为 50%，App 仍为 25%。两路检索均返回相关资料，SQL 结果与样例库核对一致。
- API 重启后确认第二份报告。前后工具执行记录均为 2 条，接收人的收件箱只增加一份该任务的报告。
- 回归测试覆盖 PostgreSQL 权限、查询超时、行数限制、非法 SQL、受控字段纠错、拒绝、过期、越权和并发确认。真实联调曾发现 SQL 白名单误拒绝正常的 `CASE WHEN`，补齐该语法并增加回归用例后重新通过。
- 浏览器验收覆盖快捷进入、图表与 SQL、CSV 导出、多轮追问、刷新恢复、规则检索、报告审批、角色切换和共享接收。网页发起任务后轮询状态与事件。
